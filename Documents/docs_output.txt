Project Scope Baseline
Project Name: Fitness tracker
Date Prepared: 2/3/2026
Prepared by: Osama Hamada / Mahmoud Aly
1. Introduction
This document defines the Scope Baseline for the Fitness Tracker System project. It formally describes the project scope and serves as a reference for scope management and change control throughout the project lifecycle.
The Scope Baseline includes the Project Scope Statement, Work Breakdown Structure (WBS), and WBS Dictionary, ensuring alignment with the approved Project Charter.
2. Project Scope Statement
2.1. Project Justification
With the growing global interest in health, fitness, and physical activity tracking, users increasingly rely on digital systems to monitor their workouts, calculate calories burned, and achieve fitness goals. Currently, many users lack a unified platform that accurately tracks physical effort per distance and provides meaningful feedback to improve health outcomes. The Fitness Tracker System is being developed to address this need by offering a web-based platform that tracks users’ physical activities, calculates burned calories, and supports goal achievement. The project aims to improve body composition, help users maintain healthy body weight, and support long-term fitness goals. Successful implementation of this project will enhance user engagement in fitness activities, provide reliable tracking of physical performance, and support healthier lifestyles while aligning with institutional goals.
2.2. Product Scope Description
The Fitness Tracker System will be a web-based application that allows users to register, log in, and track their daily physical activities. The system will calculate physical effort per distance, estimate calories burned, and generate daily activity reports. Users will also receive goal recommendations and meal suggestions to support their fitness objectives.
The platform will include activity alarms and reminders to encourage consistent workouts. The system will focus on usability, performance, and reliability, ensuring that users can easily input and review their activity data through a responsive and intuitive interface.
2.3. Project Deliverables
 Functional Fitness Tracker Website: Fully deployed and operational web-based system.
 User Registration & Authentication Module: Secure user access and validation.
 Physical Activity Tracking Module: Recording distance, effort, and calories burned.
 Meal & Goal Recommendation Module: Suggested meals and fitness goals.
 Daily Activity Reports: Automatically generated fitness summaries.
 System Documentation: Technical documentation and user guide.
2.4. Project Exclusions
 Mobile Application Development: Native Android or iOS apps are excluded.
 Hardware Infrastructure Replacement: No hardware upgrades or device provisioning.
 Payment System Integration: No subscriptions or online payments.
 Wearable Device Integration: No smart device or sensor integration in this phase.
2.5. Constraints
2.6. Assumptions
Users will manually input physical activity data.
Vendor customization will be delivered within the agreed timeline.
System requirements will remain stable after approval.
Stakeholders will provide timely feedback during testing and UAT.
Hosting infrastructure will support ≥95% system uptime.
2.7. Project Acceptance Criteria
The project will be considered successful and accepted when the following criteria are met:
The website is implemented and operational by 1 March 2026.
The system achieves at least 95% uptime.
The system successfully tracks at least 95% of the user’s physical activity per day.
Users can register and validate their accounts successfully.
Users can save and view physical activity records.
The system correctly calculates burned calories based on user activities.
The system provides meal and goal recommendations.
Daily reports are generated correctly.
The system passes User Acceptance Testing (UAT).
Final approval is granted by the project sponsor after performance validation.

1.3 System Design
This phase involves preparing the technical design of the system, including architecture, database schema, user interfaces, and reporting dashboards. The deliverable is a complete system design ready for implementation.
1.4 Development
This phase includes building all main system modules such as registration, validation, activity tracking, calorie calculation, meal recommendations, goal recommendations, alarms, and daily reports. The output is a fully developed web-based Fitness Tracker system.
1.5 Testing
This phase ensures that the system functions correctly and meets the required quality standards. It includes unit testing, integration testing, system testing, and UAT. The deliverable is a tested system approved by users and stakeholders.
1.6 Deployment
This phase includes preparing the hosting or deployment environment, publishing the website, and verifying that the system is accessible and functioning correctly in the live environment.
1.7 Project Management and Closure
This phase includes ongoing project monitoring, issue and risk management, cost and resource control, final handover, and official project closure. The deliverables are the final approved system and closure documentation.
